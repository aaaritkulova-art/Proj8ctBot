# Project Bot — Telegram-бот для управления проектами

Бот по принципу «один проект = один Telegram-чат» с хранением данных
в Google Sheets. Реализован на `python-telegram-bot` 20+ (async),
FSM через `ConversationHandler`.

## Структура проекта

```
project_bot/
├── .env.example         # шаблон переменных окружения
├── config.py             # конфигурация, логирование
├── main.py                # точка входа, регистрация handler'ов
├── handlers/               # обработчики Telegram-команд
│   ├── start.py             # /start, /help, запоминание пользователей
│   ├── project.py           # /новыйпроект (FSM)
│   ├── tasks.py              # /сверка, /моизадачи, /всезадачи, /выполнил
│   ├── protocol.py           # /протокол (FSM)
│   └── info.py                # /проект
├── services/                # сервисный слой
│   ├── google_sheets.py      # весь доступ к Google Sheets API
│   ├── project_manager.py     # бизнес-логика поверх Sheets
│   └── task_parser.py          # парсер списков задач
├── utils/
│   ├── validators.py            # валидация дат/никнеймов/ссылок
│   └── helpers.py                # даты, форматирование, статусы
└── states/
    └── conversation_states.py     # состояния FSM
```

## Важное техническое дополнение к исходному ТЗ

В ТЗ описаны три листа Google-таблицы («Инфо о проекте», «Сверки
команды», «Протоколы»). Telegram Bot API технически **не может**
отправить пользователю личное сообщение, зная только его `@username`
— нужен числовой `telegram_id`, а узнать его можно только после того,
как пользователь хотя бы раз написал боту (например, `/start`) или
написал в группе, где бот его увидел.

Поэтому бот автоматически ведёт четвёртый служебный лист
**«Пользователи»** (`username` → `telegram_id`), заполняемый на
каждое сообщение в любом чате, где есть бот. Это не меняет структуру
трёх листов из ТЗ — только дополняет таблицу.

**Важно предупредить участников проекта:** чтобы получать уведомления
и пользоваться `/моизадачи`, `/всезадачи`, `/выполнил`, каждый
участник должен хотя бы раз написать боту `/start` в личных
сообщениях.

Также в лист «Инфо о проекте» добавлены колонки, не перечисленные в
исходной таблице ТЗ, но необходимые для хранения данных, которые
`/newproject` обязан собрать: `Менеджер`, `Дата начала`,
`Дата окончания`, `Архитекторы`, `Дизайнеры`, `Соучастники`.

### Полная схема листа «Инфо о проекте»

Порядок колонок ниже — фактический (совпадает с `PROJECT_INFO_HEADERS`
в `services/google_sheets.py`). Бот ищет и пишет колонки по названию
заголовка, а не по букве, так что порядок сам по себе не критичен —
но названия должны совпадать точно.

| Колонка | Кто заполняет |
|---|---|
| `Состояние проекта` (🔴/🟡/🟢/⚪) | **вручную**, только для [дашборда](../project_dashboard) — бот не пишет |
| `Статус проекта` (Не начат/В работе/.../Закончен) | **вручную**, только для дашборда — бот не пишет |
| `ID` | бот (автоинкремент) |
| `Название проекта` | бот, при `/newproject` |
| `Текущий этап` | вручную (команда ведёт по ходу проекта) |
| `Статус (готовность)` | вручную |
| `Вопросы к Диме` / `Вопросы к Наде` | вручную |
| `Дорожная карта (ссылка)` | вручную |
| `Дата начала` / `Дата окончания` | бот, при `/newproject` |
| `chat_id` | бот, при `/newproject` |
| `Ссылка на гугл диск` / `Ссылка на яндекс диск` / `Ссылка на МИРО` | бот, при `/newproject` |
| `Официальное ТЗ на проект` / `Папка для передачи заказчику` | вручную |
| `Менеджер` / `Архитекторы` / `Дизайнеры` / `Соучастники` | бот, при `/newproject` |

## Установка

1. **Создайте бота** через [@BotFather](https://t.me/BotFather), получите `BOT_TOKEN`.

2. **Создайте сервисный аккаунт Google Cloud:**
   - Включите Google Sheets API и Google Drive API в проекте Google Cloud.
   - Создайте сервисный аккаунт, скачайте JSON-ключ (`credentials.json`).

3. **Создайте Google Таблицу** (или дайте боту создать листы
   автоматически при первом запуске — код сам создаст листы с
   заголовками, если их нет).
   - Откройте доступ на редактирование для email сервисного аккаунта
     (он указан в `credentials.json`, поле `client_email`).
   - Скопируйте ID таблицы из URL: `.../d/ЭТОТ_ID/edit`.

4. **Настройте окружение:**
   ```bash
   cd project_bot
   python3 -m venv venv
   source venv/bin/activate  # Windows: venv\Scripts\activate
   pip install -r requirements.txt
   cp .env.example .env
   ```
   Заполните `.env`:
   ```
   BOT_TOKEN=...
   GOOGLE_SHEET_ID=...
   GOOGLE_CREDENTIALS_FILE=credentials.json
   ```
   Положите скачанный JSON-ключ рядом как `credentials.json`
   (или укажите свой путь в `GOOGLE_CREDENTIALS_FILE`).

5. **Запустите бота:**
   ```bash
   python3 main.py
   ```

6. Добавьте бота в группу проекта, дайте ему право отправлять
   сообщения, и вызовите `/newproject`.

## Команды

Telegram допускает в командах бота только строчные латинские буквы,
цифры и подчёркивание — кириллица технически не работает как
настоящая slash-команда (ни в python-telegram-bot, ни на стороне
самого Telegram-клиента). Поэтому основные команды — латиница, но
бот также распознаёт кириллические варианты из исходного ТЗ как
обычный текст (текстовый алиас, не "настоящая" команда Telegram,
но работает так же).

| Команда | Кириллический алиас | Где | Что делает |
|---|---|---|---|
| `/start`, `/help` | — | группа/ЛС | приветствие и список команд |
| `/newproject` | `/новыйпроект` | группа | создаёт проект, привязывает к чату (FSM) |
| `/review` | `/сверка` | группа | добавляет список задач (FSM) |
| `/protocol` | `/протокол` | группа | добавляет список корректировок (FSM) |
| `/mytasks` | `/моизадачи` | группа → ЛС | личные активные задачи |
| `/alltasks` | `/всезадачи` | группа → ЛС | все незакрытые задачи проекта |
| `/done` | `/выполнил` | группа | отмечает задачу выполненной (FSM) |
| `/project` | `/проект` | группа | сводка по проекту в чате |
| `/cancel` | `/отмена` | во время FSM-диалога | отменяет текущий диалог |

## Формат ввода списка задач (`/review`, `/protocol`)

```
1. Разработать фасад @arch1 15.08.2026
2. Согласовать цвета @designer1 20.08.2026
3. Подготовить презентацию @manager 18.08.2026
```

Строки, которые не удалось распознать (нет `@username`, нет даты,
некорректный формат), пропускаются с явным сообщением об ошибке —
остальные строки обрабатываются нормально.

## Статусы задач

- `⏳ В работе` — назначена, срок не наступил.
- `🔴 ПРОСРОЧЕНО` — вычисляется на лету (без фоновых задач/крона),
  если срок прошёл, а статус ещё не `✅ Выполнено`.
- `✅ Выполнено` — отмечена через `/выполнил`.

Фоновых проверок просрочек и уведомлений о них нет — статус
пересчитывается при каждом запросе списка задач, как и указано в ТЗ.

## Безопасность

Не коммитьте `.env` и `credentials.json` — они уже добавлены в
